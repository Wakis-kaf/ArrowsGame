# 道具、奖励与局内体验迭代计划

## 目标

围绕轻量解压的箭头解谜循环，增加主线奖励、宝箱、局内道具、错误反馈和可切换的多平台广告中间层。

## 已确认需求

### 主线奖励

- 关卡配置可标记为宝箱关，并配置宝箱奖励。
- 入口右上角显示宝箱图标和进度；当前关卡为宝箱关时显示可领取状态。
- 通关成功后，先进入胜利界面，再弹出宝箱界面；领取结束后才能进入下一关。
- 宝箱奖励可以包含道具和金币，奖励内容由配置决定。
- 非宝箱关可配置常规金币奖励，通关后直接结算金币。

### 局内道具

- 新手关隐藏道具栏，其他关卡按配置开启。
- 局内底部显示三个道具槽：图标、数量、获得按钮。
- 获得按钮弹出获取界面。
- 获取方式支持激励广告和金币购买。
- 金币不足时隐藏金币购买入口，只保留广告入口（广告总开关关闭时显示不可用状态或隐藏，待 UI 方案确认）。
- 道具使用和获得必须写入全局存档，局内使用同时更新当前关卡状态。

### 错误反馈

- 点击错误箭头时，屏幕边缘闪红并触发震动。
- 设置中提供震动开关，关闭后不触发震动但保留视觉反馈。
- 错误反馈不能阻塞后续输入，反馈结束后继续可操作。

### 广告中间层

- 增加统一广告开关：关闭时所有广告入口统一不可用。
- 业务代码不能直接调用微信广告 API。
- 通过 `IAdService`/`AdService` 中间层适配微信及未来其他广告平台。
- 统一处理加载、播放完成、取消、失败、冷却和奖励幂等。

## 推荐模块边界

```text
GameConfig       -> 关卡奖励、宝箱、道具价格和开启条件
GameManage       -> 金币、道具、震动偏好、奖励领取状态存档
GameInventory    -> 道具/金币库存增减
GameArrows       -> 局内道具效果、错误判定、局内状态快照
GamePlay         -> 道具栏、宝箱弹窗、奖励结算和错误反馈表现
Platform/Ad      -> IAdService + WeChatAdService + 非微信占位实现
```

## 数据模型草案

- `CfgLevel.rewardGold`
- `CfgLevel.chestId`（`0` 表示非宝箱关）
- `CfgChestReward`: 奖励金币和道具列表
- `CfgInGameItem`: 道具 ID、图标、金币价格、广告奖励数量、可用关卡条件
- `ArchiveCurrency`: 金币和体力（体力与局内 Heart 分离）
- `ArchiveReward`: 宝箱/关卡奖励领取状态，保证只发放一次
- `ArchiveSettings.enableVibration`

## 首版三个道具

1. `Hint`：高亮可行箭头并显示短暂提示。
2. `Undo`：恢复最近一次有效操作，首版保存最近 1~3 步。
3. `Clear`：清除玩家选择的一条阻挡箭头。

道具效果由 `LevelVO` 执行，UI 只发送“请求使用道具”事件；奖励和广告完成后再由库存层发放。

## 广告接口草案

```csharp
public interface IAdService
{
    bool IsEnabled { get; }
    bool IsReady(AdPlacement placement);
    void ShowRewarded(AdPlacement placement, Action<AdResult> callback);
}
```

推荐的 `AdPlacement`：`ChestDouble`、`ItemAcquire`、`Revive`、`EnergyRestore`、`RewardDouble`。

## 实施顺序

1. 配置结构和存档结构：金币、道具、宝箱、领取状态、震动偏好。
2. 通关奖励和宝箱结算，确保幂等和断线/退出恢复。
3. 局内道具栏与三个道具效果。
4. 错误闪红、震动设置和移动端触感调优。
5. `IAdService` 中间层和广告获取界面。
6. 新手关隐藏、配置驱动开关、全流程回归测试。

## 验收标准

- 宝箱关只发放一次奖励，重复进入胜利界面不会重复领取。
- 非宝箱关正确发放配置金币。
- 新手关不显示道具栏，配置开启后无需改代码即可显示。
- 金币不足时金币购买入口不显示。
- 广告总开关关闭时所有广告入口行为一致。
- 错误点击闪红；震动开关关闭时不震动。
- 退出/切后台/重进后金币、道具、领取状态一致。
